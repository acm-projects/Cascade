# Editing-product replacement evaluation

Reviewed 2026-10-31. Status: research complete; no replacement integrated or quality-verified. Existing Cascade editor remains operational. No footage was uploaded to a new vendor, no account was created, and no purchase or paid API call was made. Existing credentials were checked by service name/presence only; none for the products below were configured.

## ChatCut first

ChatCut is an actual editing product with editable projects, not merely a video-generation model. Its [product documentation](https://chatcut.io/docs/what-is-chatcut) describes natural-language timeline edits and manual revisions. However, its [official integration documentation](https://chatcut.io/docs/agent-plugin) and [public plugin repository](https://github.com/ChatCut-Inc/agent-plugin) document agent-host connections, not a general-purpose embeddable Cascade editor or backend editing-agent API. The hosted MCP endpoint is public documentation, but that alone does not establish authorization or support for embedding/reselling the editor in Cascade. No supported REST editing API, SDK embedding contract, or Cascade-compatible timeline schema was located. This is a finding about public documentation, not proof that a private partner agreement cannot exist.

The [terms](https://chatcut.io/terms) authorize documented integrations and distinguish commercial use of one's outputs from reuse of the software/service. The public plugin source is not evidence that the proprietary editing engine is open source. Do not copy its software, scrape private endpoints, reuse host OAuth credentials in Cascade, or iframe the editor and call it an integration. A commercial embedded integration needs explicit vendor documentation/authorization.

ChatCut can export finished media and editable handoffs. [FCP7 XML](https://chatcut.io/docs/export-xml) can lose captions, effects, transitions, text and other properties; optional motion graphics are rendered transparent media. [CapCut/Jianying drafts](https://chatcut.io/docs/export-capcut-jianying) are Desktop-only, with unsupported-property warnings. Neither is a lossless native Cascade timeline. Importing an MP4 would flatten its layers and would not provide conversational revision of the original edit.

[Free/Pro documentation](https://chatcut.io/docs/free-and-pro) lists a cumulative 60-minute Free cloud/web export allowance and account-specific credits; [pricing](https://chatcut.io/pricing) advertises 100 credits at $21/month billed $252 annually (also displays a $25 comparison price). Checkout controls actual entitlements. Agent reasoning through the plugin uses the host allowance; generated media consumes separate ChatCut credits ([credit policy](https://chatcut.io/docs/credits-policy)). There is no verified Cascade API price. Watermark behavior was not established from the reviewed pages; do not promise watermark-free output.

### Additional $0 audit: browser engine and output evidence

**FableCut is a new, stronger candidate for a small integration experiment**, rather than a complete free AI product recommendation. Its MIT source exposes a JSON timeline, REST and MCP. Documented engine features include beat detection/cut snapping, variable-speed keyframes with export-audio retiming, transitions, local Whisper captions, ducking, EQ/compression and layered compositions. Requirements are Node 18+, Chromium and preferably FFmpeg. No dedicated NVIDIA GPU or paid account is required for those local engine operations; speech/background-removal models are separate first-use downloads. Chat intelligence remains an external agent. Smooth optical-flow slow motion and reliable creative decisions have not been established. Source: [FableCut](https://github.com/ronak-create/FableCut), [manual](https://fablecut.space/docs/).

The existing Mac was inspected earlier as M4 Pro with 24 GB unified memory. FableCut's documented runtime requirements are compatible in principle; this is not a measured export/AI memory benchmark. QCut publishes an Apple Silicon build. WeftCut requires macOS 13+; source builds need Node 24+, Rust and Xcode command-line tools. OpenChatCut needs Node 24 for source builds and uses VideoToolbox on macOS; its M4 Max benchmark explicitly should not be treated as a default for other Macs. None of these reviewed documents establishes a complete editor-plus-local-agent RAM minimum or performance guarantee for this M4 Pro. [WeftCut build requirements](https://github.com/WeftCut/WeftCut/blob/main/docs/setup.md), [OpenChatCut Mac benchmark caveat](https://github.com/0xsline/OpenChatCut/blob/main/MACOS-RENDER-TUNING.md).

- [FableCut 58-second playable MP4](https://fablecut.space/showcase/fablecut-studio-demo.mp4): a live agent/editor Reel demonstration linked by the maintainer. A workflow example, not an independently verified $0 inference run.

Product screenshots, marketing reels and successful API calls do not establish the requested output quality. ### Free-only recommendation

Do not replace Cascade's working editor yet. QCut is the first permissively licensed engine to test as a separate local sidecar; OpenChatCut is the closest agent/editor to evaluate only if its AGPL/Remotion conditions and inference requirements are acceptable. Neither removes the need for an inference source. A desktop Codex/Claude subscription is not a freely reusable inference API for Cascade's server, and a free engine is not an unlimited free editing service.

No candidate has been demonstrated on our clip to meet the target. Precise beat/action montage, artifact-free speed ramps, tracking/masks, accurate caption timing, professional sound layering and reliable preview/export roundtrip remain acceptance tests, not checked capabilities. Consequently no replacement was wired into the UI, no new MP4 was attributed to one, and no professional-quality improvement is claimed. This preserves the existing editor while reporting the actual free-product constraints.

## Paid candidate requirements (not selected)

Evaluate Rendley's actual Agent API with one disposable clip before selecting it as Cascade's replacement. It is the closest documented match to an existing product making and revising creative decisions. This recommendation concerns integration fit, not demonstrated professional editing quality. No vendor's marketing establishes precise beat cuts, good optical-flow ramps, reliable tracking/masks, coherent sound design or reference matching on our footage.

Requirements before a real trial: an authorized Rendley account with Agent API access, server-side API key, acceptance of vendor terms by the user, permission to upload a specific clip copy, and a spending limit covering editing plus export. Never put the key in Vite/client variables or chat. No reference video has been supplied/evaluated in this task.

The SDK is separately priced at $150/month Pro for a live domain; its free development tier is localhost-only. The SDK page's feature list and FAQ conflict about free-tier watermarks. Agent projects are described as SDK-compatible with possible adjustments and support involvement. Resolve these conditions with the vendor before promising an embedded manual timeline. A Studio link alone does not satisfy the Cascade integration requirement.

## Concrete integration design, pending product choice

1. Keep the current editor/default engine unchanged. Add a separately enabled external-engine path only after the product is selected. Preserve existing drafts and original media.
2. Resolve a selected clip through current owner checks, copy it, and upload through the documented vendor upload flow. Never expose Cascade's authenticated media routes publicly. References are separate authorized inputs.
3. Persist an owner-scoped external edit record with Cascade source/draft snapshot, vendor project/thread IDs, job IDs, saved project/version snapshots, and cached MP4 artifacts. Vendor state remains distinct from Cascade's incompatible edit schema; do not claim native track roundtrip.
4. Use interactive runs and display the returned plan/cost before execution. Rendley's empty approval response means approve: reject empty client approval bodies. Its reject option may skip a tool rather than abort; use the documented cancel endpoint to stop a run. No automatic paid retries after ambiguous timeouts.
5. Poll agent and export jobs separately. HTTP 200 is acceptance, not completion. Expose waiting-input, queued, running, completed, failed and canceled states accurately. Save the downloaded MP4, not an expiring signed URL. Validate the resulting media before marking it playable.
6. Follow-ups use the same external project/thread. Undo/redo needs verified vendor versions or project duplication, not an instruction to the model to recreate the past. Save/reload must retain both timeline version and rendered artifact. Never let an external response overwrite newer Cascade manual edits.
7. Embed a supported vendor SDK only after license, project compatibility, authentication and save behavior are verified. Otherwise label the trial as external output evaluation; it is not the completed replacement workflow.

## Real-clip acceptance test (not yet run against a replacement)

- Freeze a copy of the original and baseline draft. Record duration, frame rate, sample rate and transcript. Use an explicitly bounded Reel brief with opening hook, build, payoff and ending; no reference-matching claim without supplied/evaluated references.
- Obtain an MP4 from the actual engine. Watch the whole original and whole result with sound; inspect cuts and transition boundaries frame by frame. Measure onset-to-cut offsets, caption alignment and dialogue/music synchronization. Check speed-ramp interpolation artifacts and pitch/time handling, not just durations.
- Review framing, typography, grading consistency, effect restraint, masks/tracking and actual sound layers. Mark each requested technique completed, skipped, unsupported or failed based on visible/audible evidence.
- Request a specific follow-up on the same project, verify its effect and absence of unwanted collateral changes, exercise undo/redo, then reload. Compare the displayed preview with the saved exported bytes/timeline version.
- Promote the replacement only if these checks pass. Mock API tests are useful for transport/error handling but do not establish editing quality. No new replacement MP4 or quality improvement is claimed in this evaluation.
